# ADR-0002: HTTP, события и журнал сессий

- Статус: принято.
- Дата: 2026-11-06.

## Контекст и решение

Команды обоих протоколов передаются HTTP/JSON версии 0. Публичный вход — gateway с Bearer-токеном, доступный на loopback8080. Для удалённого доступа нужен SSH-туннель или TLS с проверкой сервера; открывать HTTP-порт наружу нельзя. Межсервисная сеть internal; только модельный посредник имеет выход к провайдеру.

Сессия со снимком имеет отдельный контейнер. Одна активная задача в сессии; независимые сессии могут работать параллельно. request_id и operation_id принадлежат клиенту/харнесу, не модели. SQLite хранит отпечаток запроса, состояние и события вне /work. Повтор с тем же содержимым возвращает состояние; другое содержимое с тем же ID даёт 409. Это предотвращает повторную запись READY после потери ответа. Журнал хранится до docker compose down -v.

События читаются по возрастающему seq и курсору after. Переподключившийся клиент продолжает с последнего seq. Состояние операции и финальное событие записываются одной транзакцией. После перезапуска начатый запуск становится ошибкой, а не автоматически повторяется. Отдельная пользовательская задача может исправить ошибку команды; сетевой сбой не разрешает повторить действие под новым ID.

## Альтернативы

WebSocket обеспечивает двусторонний канал, но усложняет повторное чтение и тестирование. gRPC даёт типы и streaming, но требует генерации кода. HTTP и журнал дают обозримый протокол с независимой проверкой; полный графический клиент остаётся следующим этапом.

## Ошибки и повтор

| Класс | Пример | Политика |
| --- | --- | --- |
| command_error | exit1, stderr | Результат возвращается модели; новое действие только её явным решением |
| timeout | Команда превысила срок | Контейнер удалён, запуск прекращается; автоматического повтора нет |
| sandbox_error | Контейнер исчез, менеджер перезапущен | Итог неопределён/ошибка; не повторять действие |
| transport_error | Потеря HTTP | Узнать состояние по тому же ID; не присваивать новый ID автоматически |

## Последствия и проверка

Журнал учебной сессии со снимком содержит содержимое инструментов: в публичных результатах допускаются только синтетические учебные данные. Перезапуск не восстанавливает беседу для продолжения; сохраняется наблюдаемая история, а не память работающего процесса. Отмена не откатывает внешние эффекты; текущая песочница не имеет сети, рабочая tmpfs уничтожается. Проверки: повторные запросы, конфликт ID, единственный итог, события после курсора, отмена и очистка.

## Подключённая папка

Установка принимает общий токен, а владелец создаёт дополнительный случайный ключ сессии до первого подключения. Сервер хранит проверочное значение и собственные непрозрачные номера ресурсов. При временной потере ответа владелец повторяет запрос с тем же ключом и идентификатором. Изменение тела под прежним номером получает 409. Недостаточные полномочия дают 403. Общий токен сам по себе подходил для локальных учебных снимков, но позволил бы второму клиенту читать чужие события монтирования.

Полный контекст и содержательные события доступны в памяти во время сессии. В постоянных базах обоих процессов сохраняются только технические поля. Явное завершение закрывает запись и последующие команды, в том числе точный повтор. История остаётся доступна с тем же ключом владельца. Временный обрыв соединения со шлюзом допускает продолжение чтения с последнего номера события. Потеря файлового соединения останавливает операцию. После сбоя сервера запрос с неопределённым эффектом автоматически не повторяется.
